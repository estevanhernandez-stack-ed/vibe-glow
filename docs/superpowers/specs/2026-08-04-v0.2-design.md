# vibe-glow v0.2 — design (2026-08-04)

One release, three workstreams: the launcher campaign's retro remediation folded into the command texts, a concierge entry point (one call, no stage knowledge required), and scoped campaigns (one app area + a user goal). Plus the retro's biggest adapter ask, promoted on Este's call: UIA-driven capture.

Input: `docs/dogfood/626-mod-launcher-2026-08-04.md` (first full campaign retro — identity → 46-finding audit → 8 waves → Forge reveal as launcher v0.16.0) plus the v0.1 execution ledger's hardening list.

Decisions locked during brainstorm (2026-08-04, Este's calls):

- **One release.** v0.2.0 ships everything together — remediation and features touch the same files; splitting means editing the same text twice.
- **Scoped stage 0 extracts, never invents.** A scoped campaign writes a conventions brief from what the app already does; concept boards stay app-wide-only.
- **Next dogfood: RoRoRo settings section** (WPF, .NET 10), scoped, goal "easier to navigate," started through the concierge.
- **UIA-driven capture builds now**, not v0.3 — the next campaign is Windows-native and will use it.
- **`schemaVersion` stays 1.** Every new state key is optional with a tolerate-absence rule; the launcher's existing `stage: "done"` file keeps parsing untouched.
- **Adapter id stays `winui-powershell`.** PrintWindow + UIA cover WPF/Win32 too; we document the coverage rather than rename and orphan recorded state.
- **Consent-gated chaining is lawful; auto-advance stays forbidden.** The concierge may run a stage after an explicit yes; nothing ever runs without one.

## 1. Remediation — retro lessons become permanent text

File-by-file:

- **commands/audit.md**
  - Lens instruction: findings whose fix implies a *new platform mechanism* (not a re-style) get flagged `[new-mechanism]` in the fix direction — they price differently and must not sit in the register priced as re-styles (retro: F-002 sat six waves).
  - Accessibility lens: check declaration/tab/UIA order against visual/column order — geometry changes that leave focus order behind are findings (retro: wave-8 column swap).
  - QOL lens: ask "what state survives a restart" for every stateful surface in evidence (retro: theme persistence surfaced only at reveal).
- **commands/wave.md**
  - Scoreboard law: any tally or "N open at severity X" claim is re-derived from register rows at the moment of writing — never carried forward from a previous wave's summary (retro: the wave 6–7 false claim cost wave 8).
  - Step 3 explicitly sets the wave's ledger `status: "shipped"` on merge (closes the v0.1 transition gap).
  - Close-out checklist added to step 4: grep comments near changed surfaces for claims the change contradicted (retro: two stale comments survived their code); timing-dependent fixes verified at least twice (retro: the popup `Opened` race); a domain-guard reviewer (e.g. core-purity) runs whenever the repo has one and its domain was touched.
- **commands/identity.md**
  - Step 1 ends by writing `.vibe-glow/state.json` with `stage: "identity"` — mid-flight resume becomes real (codifies what the launcher session improvised).
  - Step 2 reuses an existing capture checklist when one is present in the target repo instead of enumerating fresh.
- **commands/reveal.md** — sets `stage: "reveal"` on entry, `"done"` on close (kills the dead enum value); the adversarial precondition re-derive (from register rows, never wave summaries) is called out as load-bearing — the retro credits it with saving the campaign.
- **commands/status.md** — "from files read this invocation" extends explicitly to "never from wave summaries; tallies re-derive from register rows."
- **docs/state-schema.md** — documents the `reveal` transition and the new optional keys (§3); adds the optional-key law: readers tolerate absent keys, writers preserve keys they don't understand.
- **docs/state.example.json** — findings-register filename gains the `<app>` segment (fixture matches the convention it models).
- **CHANGELOG.md** — v0.1.0 entry's "five stage commands (… status)" wording corrected (status is the read-only reporter); v0.2.0 entry added.
- **tools/lint-plugin.ps1** — frontmatter check tightened: `description:` must appear between the opening `---` and closing `---`, not merely in the first five lines.

## 2. The concierge entry

`commands/vibe-glow.md` is rewritten from signpost to front door. Behavior:

- **No state file:** three-sentence intro, then one question: *"Full glow-up of the whole app, or a focused fix on one area?"* If focused: two follow-ups — which area, and what should be better about it (the goal, in the user's words). Then: *"Start now?"* On yes, run stage 0 itself — full identity for app-wide, the scoped path (§3) for focused — without the user ever hearing the word "stage." Answers the concierge collected (area, goal) pass into stage 0's interview; it never re-asks them. On no or silence, stop.
- **State exists:** report where the campaign is (today's router behavior), then offer to run the recommended next stage — *"Run it now?"* — and on yes, do so. One stage per consent; the next gate always comes back to the user.
- **Broken state:** unchanged from v0.1 (say which key, never guess), plus one addition: a `stage` value outside the enum is named as such (closes the v0.1 fallthrough).
- Command frontmatter descriptions across all six files rewritten so the picker teaches: vibe-glow.md reads "Start here — one call runs the whole campaign, no stage knowledge needed."

The no-auto-advance law survives intact: every stage run is preceded by an explicit yes in the same conversation.

## 3. Scoped campaigns

**State:** one new optional key —

```json
"scope": {
  "area": "settings",
  "goal": "easier to navigate",
  "surfaces": ["06-settings-dialog", "..."]
}
```

Absent `scope` = app-wide campaign, byte-for-byte today's behavior. `surfaces` lists checklist row names in scope; the concierge or `:identity` fills it during the interview.

- **Scoped stage 0 (identity.md gains a scoped path):** capture the scoped surfaces plus one hop of visual neighbors (the surfaces a user reaches the area from — context for the consistency lens). Then **extract, don't invent**: write a *conventions brief* at `docs/superpowers/specs/YYYY-MM-DD-<app>-<area>-conventions.md` — observed type/spacing/component patterns in the app, the user's goal verbatim as the north star, invariants (interviewed the same as app-wide). No concept boards, no theme stress-test beyond what the app's own theming demands. The brief is the measuring stick; reviewers argue conformance-to-conventions and progress-toward-goal, never taste.
- **Scoped audit (audit.md):** same five lenses, scoped evidence only. The goal weights the ranking — QOL/flow findings that serve the stated goal take visibility precedence; the consistency lens compares the area against the rest of the app (does settings drift from the app's own patterns). Cost gate scales with surface count and says so (a settings-section audit is a fraction of 22 surfaces — quote the smaller number honestly).
- **Waves:** unchanged. Findings are findings.
- **Scoped reveal (reveal.md):** detects `scope` and runs a light close-out — final re-capture of scoped surfaces, goal-check ("is it easier to navigate, per the register's closed findings"), state to `done`, retro to `docs/dogfood/`. No flagship theme, no marketing beat — flagships are app-wide by nature. The §1 entry/exit transitions (`"reveal"` on entry, `"done"` on close) apply in both modes.

## 4. UIA-driven capture

The retro's wave-8 pattern, promoted to a first-class adapter mode (works on WPF and WinUI both — System.Windows.Automation):

- **`capture.ps1` gains `-Uia` mode:** reads a per-app **route map** (`docs/ui-routes.json` in the target repo, camelCase) — `[{ "surface": "06-settings-dialog", "invoke": ["Settings"], "close": ["Cancel"] }]` where `invoke`/`close` are ordered automation-id-or-name element paths. For each route: find + invoke via UIA, wait for the window/dialog idle, capture through the existing PrintWindow path with the route's surface label, close via UIA invoke — never Esc, never keyboard. Routes that fail to resolve are reported and skipped, not fatal — the human watch mode remains the fallback for what UIA can't reach.
- **`-DumpUia` flag** (any mode): writes `<capture-name>.uia.txt` beside each PNG — the window's UIA tree with names, roles, and automation ids. Closes half the Narrator-verification gap and doubles as route-map authoring material.
- **`sample.py`** ships beside capture.ps1: crop a region and walk pixel values (PIL) — the retro's answer to the deceptive-downscale problem (filled-vs-outlined at preview scale, invisible halos). Python is an optional dependency; the script says so.
- **README field notes** section (new): popup `Opened` races content wiring — key one-shot template fixes off the injected content's `Loaded`; stock Title ContentControl pins HorizontalAlignment=Left; ContentDialog UIA name derives only from string Titles (element content silently drops the accessible name); Esc collides with watch mode (mooted under `-Uia`); interaction states (hover, drag, flyouts, transitions) remain uncapturable by screenshot — verify by code or by sample.py, and say which.
- **Mode guidance in the README:** `-Uia` preferred where a route map exists; watch mode for humans and unreachable states; single mode for one-offs.
